# Work plan

Phases are small and reversible. Phases 1 to 4 each end with a phase checkpoint (`review-phase`, run in a fresh session) before the next phase is planned; it checks for architecture drift across tasks. Phases 2.1 and 4.1 are small follow-ups to a closed phase and have no checkpoint of their own: each task goes through `review-task`. Budget: the original plan was 8 hours including setup and documentation; it is now about 12h (see the time log and [ADR-010](adr/010-postgres-data-layer.md), [ADR-011](adr/011-local-first-delivery.md)). Record actual time in the table at the end.

## Phase 2.1: AI boundary follow-ups (about 50 min, estimate)

Added 2026-10-15 after the Phase 2 checkpoint, from a comparison with an earlier project's LLM pipeline (patterns only, no code or data copied). Both tasks change the result types, schema or prompt that Phase 3 consumes, so they land before the routes and the request log line, not after.

- [x] Keep the failure reason, so the Phase 3 log line can say why a request fell back (`interpretQuery` used to drop the reason and `explainResults` fell through). `Interpretation.failure` and `Explanations.failure` carry the last failure reason, set only on fallback after a model call: a lib/ai reason or, for the services' own checks, `invalid_filters` and `ungrounded`. Done 2026-10-15: a test per reason with the mock client, 166 unit tests in all; failure-modes row and Phase 2 notes in [architecture](architecture.md) updated; [ADR-005](adr/005-llm-provider.md) lists no reasons (only the `stop_reason` check), so no superseding note. `PROMPT_VERSION` unchanged. - [x] Deferred, not built (decided 2026-10-15): constrain `offerId` in the explain schema. The idea was a per-request `enum` of the IDs sent, so an invented ID cannot be produced, with `groundExplanations` as the backstop and a `PROMPT_VERSION` bump. Not worth the risk now: the Anthropic structured-outputs page says a new schema adds latency while its grammar compiles (cached 24 hours), and the enum differs on almost every request, so most explain calls would pay it, inside the 8000 ms timeout. That cost was not measured here, and the gain is small, because an unknown ID already makes `groundExplanations` reject the answer and every offer shows its deterministic line (ADR-002). Revisit if the Phase 3 log line shows `ungrounded` failures at a rate that matters; then measure the compile latency with one live call before adopting it, and keep the static schema if it is clearly worse (a heuristic: past about 5 s). Nothing in the code or `PROMPT_VERSION` changed
