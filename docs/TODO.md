# Work plan

Phases are small and reversible. Phases 1 to 4 each end with a phase checkpoint (`review-phase`, run in a fresh session) before the next phase is planned; it checks for architecture drift across tasks. Phases 2.1 and 4.1 are small follow-ups to a closed phase and have no checkpoint of their own: each task goes through `review-task`. Budget: the original plan was 8 hours including setup and documentation; it is now about 12h (see the time log and [ADR-010](adr/010-postgres-data-layer.md), [ADR-011](adr/011-local-first-delivery.md)). Record actual time in the table at the end.

## Phase 2: AI layer (2h25)

- [x] Deferred, not built (decided 2026-10-15): constrain `offerId` in the explain schema. The idea was a per-request `enum` of the IDs sent, so an invented ID cannot be produced, with `groundExplanations` as the backstop and a `PROMPT_VERSION` bump. Not worth the risk now: the Anthropic structured-outputs page says a new schema adds latency while its grammar compiles (cached 24 hours), and the enum differs on almost every request, so most explain calls would pay it, inside the 8000 ms timeout. Revisit if the Phase 3 log line shows `ungrounded` failures at a rate that matters; then measure the compile latency with one live call before adopting it, and keep the static schema if it is clearly worse (a heuristic: past about 5 s).
